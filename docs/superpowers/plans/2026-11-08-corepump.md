# CoroPump Implementation Plan

> **For agentic workers:** Cursor executes the C-tasks (engine). Claude executes the K-tasks (UI, review, cases) with superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax. One task is one branch and one PR.

**Goal:** Rename Impella to CoroPump across the site, then add a 3D pump, a simulated console pane, a control panel, and purge, thrombus and hemolysis physics, and 11 new teaching cases.

**Architecture:** Cursor owns everything the engine and its data contract touch (`src/physics`, `src/config`, `src/sim`, `src/mcp`, `scripts`, engine tests) and the pure, DOM-free case rules (`src/cases/orders.ts`, `gate.ts`, `spec.ts`, `markdown.ts`, `src/sim/labs.ts`). Claude owns everything a person sees or reads (`src/page`, `src/panels`, CSS, HTML, `src/library`, the case content files in `src/cases/`) and reviews every Cursor PR against a gate. A typed contract (Task C2) lands first so Claude can build UI against stub values while Cursor builds the physics.

**Tech Stack:** TypeScript, Vite, vitest, three.js. DOM-free core engine in `src/physics/core/`.

**Spec:** `docs/superpowers/specs/2026-11-07-corepump-design.md`

## Global Constraints

- Branch every task from `origin/main`, never from the stale `echo-atlas` checkout. Run `git fetch origin` first.
- American English everywhere: UI copy, docs, comments, commit messages.
- User-visible name is "CoroPump" (models: CoroPump 2.5, CP, 5.5, RP). No "Impella" anywhere after C1, except the alias list in `ALIAS_ALLOWLIST` (C1).
- Constants live in `src/config/`, tagged `[lit]` or `[assumed]`. Every number in this plan marked "starting point" is `[assumed]`. Do not copy manufacturer data.
- Every new output has a unit and range in its doc comment.
- `npm run typecheck` and `npm test` pass before every PR. Existing fixtures in `tests/fixtures/` are never hand-edited.
- Engine benchmark (`scripts/bench-engine.ts`) stays at or above 20x real time. Halving dt changes MAP, CO, device flow by under 0.5%.
- UI rules from `CLAUDE.md`: square hairline frames, no `backdrop-filter`, no tinted callouts, no gradient text or glow, no emoji, color means physiology (red, blue, amber for abnormal, cold, caution only), caption every figure and table, ECG stays on pink paper, thermal ramp for data graphics.
- Case system (PR 87 plus the `case-screen` branch): the learner may treat, never create disease. `TREATMENT_KEYS` in `src/cases/gate.ts` is a fail-closed allowlist; nothing new is treatable unless it is listed there with a one-line reason. The case author's own path (start state, checkpoint patches, opening) is never gated.
- A case monitor lists only displays (`monitor` and `panel` groups of `src/cases/orders.ts`); labs and bedside results are ordered, with turnaround compressed by `effectiveDelayS`.
- Simulation clock: 1 simulated second is 2 clinical minutes at 1x (6 and 12 at 3x and 6x). All new time constants are in clinical minutes.

## Review Focus

Failure modes the spec implies that no single feature test covers. Each has a test in the task named.

1. An old saved patient or MCP call using `devices.impella` or `support.impella` still loads, maps to CoroPump, and returns a warning (C1).
2. Out-of-range purge input (`heparinUml` of -5, 1e6, NaN; unknown solution or line string) is clamped with a warning and never throws (C3).
3. Thrombus and free hemoglobin behave the same at 1x, 3x and 6x clinical speed (C4, C5).
4. Removing the pump resets thrombus and purge; the patient's free hemoglobin keeps clearing. Re-placing starts a fresh pump (C4, C5).
5. In a running case (and through `corosim_adjust`) the learner cannot set `position`, `purge.line`, `initial` or any hidden state, so cannot create a malposition, a blocked line or a thrombus. They can set level, model, solution, heparin, and fire `reposition`, `purge.clearLine` and `exchange` (C1, C6b).

Also required in K3: the pane does not rely on color alone for alarms, and is usable at 375 px width and in dark mode.

## Deviations from the spec

- The spec had a hemolysis alarm on the console. A real console does not show free hemoglobin. It is a lab value, so the pane shows it in a separate "Labs" line, and urine color is shown beside it. No console alarm.
- The spec's control list gains "exchange pump", the only fix for advanced thrombus.
- `thrombusBurden` is in the readout for tests and debugging only. The pane never displays it.
- Free hemoglobin is an ordered lab with turnaround (`pfhb` analyte, panel "hemolysis"), and urine color is a bedside item, both in the case order catalog. In free play (no case) the pane also shows them live in a labs line.
- The console is a workspace panel (`coropump`) that a case monitor can list or the learner can order, not a hand-mounted block in `sim/index.html`. The 3D pump follows the heart stage's own visibility (`stageVisible`).
- The learner may reposition, clear the purge line and exchange the pump (one-shot treatments). They may not set `position`, `purge.line` or `initial`; those are the case author's disease controls.

## Contract (defined in C2, used by both sides)

```ts
// src/config/devices.ts
export type CoroPumpModelName = "2.5" | "CP" | "5.5";
export type CoroPumpPosition = "correct" | "aortic" | "deep";
export type PurgeSolution = "dextrose-heparin" | "bicarbonate";
export type PurgeLine = "clear" | "kinked" | "blocked";

// src/sim/patient.ts  (DeviceSpec)
coroPump?: {
  model?: CoroPumpModelName; level?: number /* P0..P9 */; position?: CoroPumpPosition;
  purge?: {
    solution?: PurgeSolution; heparinUml?: number /* 0..50, default 25 */;   // treatment
    line?: PurgeLine /* default "clear" */;                                    // disease: author and free play only
    clearLine?: boolean;                                                       // treatment, one-shot: line back to "clear"
  };
  exchange?: boolean;    // treatment, one-shot: new pump, thrombus 0, purge reset
  reposition?: boolean;  // treatment, one-shot: position back to "correct"
  initial?: { thrombusBurden?: number /* 0..1 */; plasmaFreeHbMgDl?: number }; // disease: lets a case start "day 3 on the pump"
};
coroPumpRp?: { level?: number };

// src/sim/coreDevices.ts
interface CoroPumpReadout {            // existing ImpellaReadout fields, unchanged, plus:
  purge: { solution: PurgeSolution; heparinUml: number; line: PurgeLine; flowMlHr: number; pressureMmHg: number };
  hemolysis: { plasmaFreeHbMgDl: number; urineColor: "clear" | "tea" | "dark" };
  thrombusBurden: number;              // 0..1, truth for tests and debugging; never on the console
  waveform: { dtMs: number; inletMmHg: number[]; currentMa: number[] } | null; // last completed beat, 100 points each
  alarms: string[];                    // adds "PURGE PRESSURE HIGH" and "PURGE FLOW LOW"
}
interface DevicesReadout { coroPump: CoroPumpReadout | null; iabp: IabpReadout | null; ecmo?: EcmoReadout; coroPumpRp?: CoroPumpRpReadout }
```

### Task C3: Purge model

**Files:**
- Create: `src/physics/core/devices/purge.ts`
- Modify: `src/config/devices.ts` (`COROPUMP_PURGE`), `src/physics/core/devices/coroPump.ts` (taps), `src/sim/coreDevices.ts`
- Test: `tests/purge.test.ts`

**Interfaces:**
- Produces: `purgeState(input: { solution: PurgeSolution; heparinUml: number; line: PurgeLine; thrombus: number; running: boolean }): { flowMlHr: number; pressureMmHg: number; alarms: ("PURGE PRESSURE HIGH" | "PURGE FLOW LOW")[] }`. Pure function.

Starting points: resistance multiplier m = lineMult x (1 + 3 x thrombus^2) x solutionMult, with lineMult clear 1, kinked 2.5, blocked 10 and solutionMult dextrose-heparin 1, bicarbonate 0.85.
